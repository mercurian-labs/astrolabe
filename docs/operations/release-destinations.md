# Astrolabe release destinations

> For maintainers. Status of each place an Astrolabe build can ship to, and what unblocks the
> ones that cannot yet. The mechanics live in [release.md](./release.md).

Last reviewed: 2026-09-16. `main` is based on upstream T3 Code at `2a264adc6f` (pingdotgg/t3code,
2026-09-15), reset on 2026-09-15 with zero divergence at that point; the previous fork line is the
`old` branch and the `old-main` tag. Credentials are inventoried in [credentials.md](./credentials.md).

| Destination                              | Status                                              | What is in place                                                                                                                                                                                                         | What unblocks it                                                                                                                            |
| ---------------------------------------- | --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------- |
| macOS desktop (signed, notarized DMG)    | **Ready**                                           | Proven by preview run 35143038061 on 2026-09-16: signed with the Developer ID certificate and notarized, no passkey profile; app id `com.mercurian.astrolabe`; the app inside the DMG assesses as Notarized Developer ID | A release run. A team's first notarization submissions can sit in Apple's queue past the 30-minute job timeout; later ones take minutes     |
| Linux desktop (AppImage)                 | **Ready**                                           | Builds unsigned as upstream does; `astrolabe` executable and Mercurian desktop entry                                                                                                                                     | A release run                                                                                                                               |
| Windows desktop (NSIS installer)         | **Ready, unsigned**                                 | Builds; Azure Trusted Signing is optional                                                                                                                                                                                | Azure Trusted Signing account and its seven secrets, if signed installers are wanted; deliberately deferred                                 |
| CLI archives on GitHub Releases          | **Ready**                                           | `astrolabe-<version>-<platform>` archives, `SHA256SUMS`, install scripts and self-updater pointing at mercurian-labs/astrolabe                                                                                           | A release run                                                                                                                               |
| CLI on npm (`@mercurian/astrolabe`)      | **Published, launcher install under investigation** | All six packages exist with trusted publishing for `.github/workflows/release.yml`; the 2026-09-16 preview run published `0.0.41-preview.20260916.109` under the `preview` dist-tag                                      | Confirm `npx @mercurian/astrolabe@preview` installs its platform package; consider staged publishing before the first public stable release |
| Nightly channel and desktop auto-update  | **Ready to enable**                                 | Scheduled nightlies and update feeds derive from this repository; macOS signing and npm publishing are proven                                                                                                            | Enable the Release workflow deliberately; nightlies fire twice an hour once it is on                                                        |
| Arch Linux (AUR)                         | **Blocked on rename**                               | Inherited `t3code-bin` and `t3code-nightly-bin` packages still name upstream's repository and artifacts                                                                                                                  | Mercurian package names, sources, and an AUR maintainer account; follow-on Linux distribution issue                                         |
| iOS and Android test builds (Expo / EAS) | **On hold**                                         | Upstream mobile app builds; identifiers still upstream's                                                                                                                                                                 | Deliberately deferred until branding lands: Mercurian bundle identifiers, an Expo project, push credentials                                 |
| iOS App Store and Google Play            | **Blocked**                                         | Nothing Mercurian-specific                                                                                                                                                                                               | Organization D-U-N-S number for the store accounts, the finished brand assets, and the test builds above                                    |
| Hosted web app (Vercel)                  | **Out of scope**                                    | Upstream's deploy steps are skipped without Vercel secrets                                                                                                                                                               | Not planned for the first milestone                                                                                                         |
| T3 Connect relay and sign-in             | **Parked**                                          | No relay, Clerk, or Cloudflare relay configuration; builds ship with Connect absent                                                                                                                                      | Not planned; reviving it is a product decision, not a setup step                                                                            |

Related repository state: the `Release`, `Deploy T3 Connect relay`, and mobile workflows are
disabled in the Actions UI. The only secrets present are the release GitHub App credentials and
the Cloudflare pair inherited from the previous landing-site deploy.
