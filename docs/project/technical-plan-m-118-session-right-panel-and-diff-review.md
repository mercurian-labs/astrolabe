# Technical Plan — M-118: Coding Session View: right panel and diff review loop

_Generated from the Goal/AC on Linear issue M-118 (2026-08-20). Grounded against `main` at `97242f6bd`, after M-117 gave the session screen its own header and entry points. Product sources consulted in the almagest vault as of `652b329`: **Coding Session View** (right panel, review loop), **T3code Thread View** (the built referent), **Splits** ("position is the stamp"), **Plans** (review-comments resolution: "the original of the loop"), **Coding Sessions** (leaf-record resolution: the recorded facts are the base commit and that point's plan revision), **Checkpoint Graph** (position honesty copy). Governing ADRs: 001 (`docs/architecture/local-first-runtime.md`), 002 (`docs/architecture/event-streaming-model.md`), 004 (`docs/architecture/fork-baseline.md`)._

**Goal, in one sentence:** re-house the fork's right panel on the session screen — terminal, files, diff (turn / whole session / working tree, with whitespace and word-wrap toggles), browser preview, and a new **Plan** tab showing the exact plan revision the session implements — with the diff's line-comment → composer-chip → send loop working end to end, and no plan-mode proposals surface anywhere.

**Scope fences:** M-114 owns the runtime and composer mechanics (chips, pickers, send/stop); M-117 owns the header, entry points, and revert — all shipped. 065 (M-119) owns git actions, the open-in picker, and repository scripts (including scripts that declare preview addresses); M-115/066 owns teardown. This plan adds **no contract, migration, RPC, or server change of any kind** — every server surface it needs (`fullThreadDiff`, `getPlanTextAt`, port discovery, terminal manager, checkpoint diffs) already exists. Mobile stays parked (ADR 004).

**Vocabulary:** "the panel" is `ChatView`'s right panel (`rightPanelStore` surfaces); "plan tab" always means the session's standing plan — t3code's plan-mode proposals tab no longer exists upstream (removed at storage v9) and plan mode itself was surface-stripped at M-114.

## Discovery Summary

**Most of the panel is built and mounted; two ACs are broken by precise, small gaps, and one tab is net-new.**

**The tab machinery is live at the session route.** `ChatView` renders the tab strip (`RightPanelTabs.tsx`) and content switch (`ChatView.tsx:5899-5969`) for `preview | terminal | diff | files | file | agents` surfaces, per-thread and persisted (`rightPanelStore.ts:17-47,53-60`). The session route is `ChatView`'s **only** consumer, so panel work lands exactly one place. Availability gates exist per tab (`browserAvailable` = Electron runtime, `diffAvailable` = server thread + git repo, `filesAvailable` = project open; `ChatView.tsx:6380-6383`).

**The plan-mode proposals tab already does not exist.** Upstream removed the `plan` surface kind at storage v9 ("plans render inline in the transcript", `rightPanelStore.ts:50-51`; the migration drops legacy plan surfaces at `:183`), and the fork stripped plan mode itself at M-114 (`ChatView.tsx:1494-1499` forces `interactionMode` to `"default"`; the `/plan` slash path and mode toggles are deleted; ADR 004 §2 records it). AC 1's negative clause is **verified, not built** — the walk asserts it.

**The diff tab is unreachable on the session screen — the first real gap.** `DiffPanel` resolves its thread from route params requiring **both** `environmentId` and `threadId` (`DiffPanel.tsx:330-334`, `resolveThreadRouteRef` in `threadRoutes.ts:68-76`), but the session route declares only `$threadId` (environment comes from `usePrimaryEnvironmentId()`). `activeThread` is therefore null and the panel renders "Select a thread to inspect turn diffs" — taking the changed-files card wiring (`ChatView.tsx:5836-5844`: `selectTurn` + `open(ref,"diff")`, already correct) and the whole review loop down with it. The thread routes are parked (`threadRoutes.ts:58-63`), which is why this regressed silently.

**Diff scopes: two of the AC's three exist; "whole session" is new UI over an existing endpoint.** `diffPanelStore` selections are `branch | unstaged | turn` (`diffPanelStore.ts:8-11`) with working-tree ("unstaged", `git diff HEAD` + untracked, `GitVcsDriverCore.ts:2165-2197`) the default on a dirty tree, and per-turn checkpoint diffs (`CheckpointDiffQuery.ts:82-187`). Whitespace and word-wrap toggles are built (`DiffPanel.tsx:316-317,1006-1047`). The whole-session diff — turn-0 checkpoint → latest checkpoint — exists server-side as `fullThreadDiff` (`CheckpointDiffQuery.ts:189-281`) and the client query already routes `fromTurnCount === 0` to it (`queries.ts:358-368`); no UI selection reaches it today.

**The review loop is built end to end, with one honest gap against the AC.** Line selection + gutter button on the annotatable diff (`AnnotatableCodeView.tsx:205-252`), comments anchored to `filePath` + diff-row `startIndex`/`endIndex` with a human `rangeLabel` (`reviewCommentContext.ts:4-34,399-437`), staged per-thread as removable chips above the prompt (`ComposerPendingReviewComments.tsx`, `ChatComposer.tsx:2816-2827`), serialized as `<review_comment …>` blocks appended to the outgoing message (`ChatView.tsx:4947-4950`), cleared on send (`:5019-5020`) and restored on failure (`:5145-5175`). Commenting works per scope via `reviewSectionId` (`DiffPanel.tsx:418,427-431`). **The gap:** `addReviewComment` dedupes by `id` only (`composerDraftStore.ts:3314-3331`), and every new draft gets a fresh id — re-commenting the same lines **stacks a second chip** instead of replacing, against the AC's "replaced if you comment on the same lines again".

**Terminal: AC 2 is already mechanically true.** Every terminal-open path passes `cwd = worktreePath ?? workspaceRoot` (`ChatView.tsx:2547-2551` via `projectScriptCwd`, `packages/shared/src/projectScripts.ts:11-18`; open paths at `:2746-2863,3224-3252`), and M-110's birth sets `worktreePath` on the thread before any turn (`CodingSessionService.ts:369-384`) — the session's terminal opens in the worktree with no change. Attach-to-composer is the selection context menu's "Add to chat" (`ThreadTerminalDrawer.tsx:484-575`), landing as inline Lexical chips serialized through `appendTerminalContextsToPrompt` (`terminalContext.ts:211-221`); it is prop-driven and works at the session route.

**Browser preview: the gating is built; the offer has lost its home.** Desktop-only support is `isPreviewSupportedInRuntime()` (`previewStateStore.ts:451-454`); the web client shows the Browser tab disabled with "Browser previews are only available in the Astrolabe desktop app." in both the + menu and the empty-state grid (`RightPanelTabs.tsx:56-60,194-209,469-476`) — AC 5's second half is verified, not built. Port discovery runs per environment with thread attribution via the spawning terminal's PID (`PortScanner.ts`, `Manager.ts:1203-1207`; `useThreadDiscoveredPorts`, `portDiscoveryState.ts:20-32`), and `openDiscoveredPort` opens the preview surface (`preview/openDiscoveredPort.ts:13-28`). But the only unprompted "offers itself" affordance — the per-thread port chip — lives in `LegacySidebar.tsx:376-440`, which is **no longer mounted anywhere**. The offer needs a Mercurian home on the session screen.

**The Plan tab is net-new, and every ingredient exists.** The session's leaf commit id is on the tree scan the route already does (`PlanCodingSessionRecord.commitId`, `contracts/mercurian.ts:81-93`); the leaf's timeline item carries `planRevisionCommitId` — the exact revision the session implements, resolved at birth by walking ancestors from the base (`PlanningStore.ts:2137-2160`) — and `parents[0]` is the base commit (`resolveActingHead` already makes this hop, `PlanPosition.logic.ts:42-50`). Plan text at that revision comes from the existing `getPlanTextAt` RPC (`useGetPlanTextAt`, `state/mercurian.ts:249-255`; server walk `PlanningStore.ts:2483-2509`). Rendering precedent: `PlanArtifactBody` (`PlanArtifact.tsx:112+`, ReactMarkdown + GFM + sanitize — deliberately not `ChatMarkdown`). "Moved past" precedent: `planMovedPastSplit` (`PlanNodePopover.logic.ts:78-88`) with the copy "Planning has moved past this plan for <repo>" (`PlanNodePopover.tsx:338-342`) — computed today only for split-revision nodes, never for a session leaf.

**Kept deliberately, though the vault doesn't mention them:** the `agents` tab (upstream's subagent fleet view — working-tree machinery a session legitimately has) and the bottom terminal drawer. M-117's rule applies: vault omission is not removal; stripping would be a vault-cited act this issue doesn't have.

## Design

### 1. The diff tab works at the session route: `DiffPanel` takes its thread by prop

Add an optional `threadRef?: ScopedThreadRef | null` to `DiffPanelProps` (`DiffPanel.tsx:298-302`); resolve `const activeThreadRef = props.threadRef ?? routeThreadRef` and use it everywhere `routeThreadRef` is used today. `ChatView` passes `threadRef={activeThreadRef}` at the one render site (`:5931-5939`). The route-params fallback stays so the parked thread routes keep working unchanged if revived. This is the smallest edit that makes the changed-files card (`ChatView.tsx:5836-5844`), all diff scopes, and the review loop functional on the session screen; making `resolveThreadRouteRef` environment-aware was rejected because the session route has no `environmentId` param by design (primary-environment resolution is the route's own job, `_chat.sessions.$threadId.tsx:81`).

### 2. The whole-session scope joins the diff panel

Add a `{ kind: "session" }` selection to `DiffPanelSelection` (`diffPanelStore.ts:8-11`) with a `selectSessionScope` action beside `selectGitScope` (`:42`); `reconcileTurnSelection` (`:95`) leaves it untouched. In `DiffPanel.tsx`:

- the scope dropdown (`:748-818`) gains **"Whole session"** between "Branch changes" and "Latest turn", disabled until the thread has a checkpoint;
- selection maps to the existing checkpoint query with `fromTurnCount: 0, toTurnCount: latestTurn.checkpointTurnCount` — `useCheckpointDiff` already routes `fromTurnCount === 0` to `fullThreadDiff` (`queries.ts:358-368`), so **no server or contract change**;
- `reviewSectionId` becomes `"session"` and `reviewSectionTitle`/scope label **"Whole session"** (extending the derivations at `:418,427-431`), which makes line comments on the whole-session scope work through the existing anchor machinery for free;
- whitespace and word-wrap toggles apply as they do to every scope (already threaded, `:448,1158,1181-1182`).

Upstream's "Branch changes" scope stays: the AC enumerates three scopes but does not forbid the fourth, and it becomes genuinely useful once M-119's git actions land commits on the session branch.

### 3. Re-commenting the same lines replaces the chip

In `composerDraftStore.addReviewComment` (`composerDraftStore.ts:3314-3331`), widen the dedupe filter from `entry.id !== comment.id` to also drop entries with the **same anchor**: equal `sectionId`, `filePath`, `startIndex`, and `endIndex`. Same-id re-adds (the file viewer's live index remap, `FilePreviewPanel.tsx:481-491`) keep working — the id clause remains — and two comments on genuinely different ranges still coexist. Chips stay removable (`removeReviewComment`, the ✕ at `ComposerPendingReviewComments.tsx:28-56`) and send-carried-then-cleared exactly as built. The vault's wording ("replaced if you comment on the same lines again") is implemented literally as exact-range replacement; overlapping-but-different ranges are distinct comments.

### 4. The Plan tab: a new singleton surface, its content composed by the route

**Store (upstream, additive):** add `"plan"` to `RIGHT_PANEL_KINDS` (`rightPanelStore.ts:17-25`), a `{ id: "plan"; kind: "plan" }` variant (`:27-47`), and a `singletonSurface` case (`:93-104`). `RIGHT_PANEL_STORAGE_VERSION` stays 9 and the migration stays byte-identical: it runs only for pre-v9 states, where dropping _legacy_ plan surfaces (t3code proposals) remains correct; the new kind never passes through it. `open()`'s type (`Exclude<RightPanelKind, "file" | "terminal">`) admits `"plan"` automatically.

**Tab strip (upstream, additive):** `RightPanelTabs` gains a `planAvailable` prop beside `browserAvailable`/`diffAvailable` (`:48-52`), a "Plan" title (`surfaceTitle`, `:222-246`), an icon (`SurfaceIcon`, `:274-297` — `ScrollText`), a + menu entry, and an empty-state action, each rendered only when available — a hidden tab, not a disabled one, because a thread with no owning plan (the route's dangling-thread tolerance) has nothing to explain.

**ChatView seam (upstream, one prop — M-117's pattern):** `planPanel?: ReactNode` on `ChatViewProps` (`:488-510`). `planAvailable = planPanel !== undefined`, passed to both tab-strip renders (`:6360-6386, 6388-6417`); an `addPlanSurface` callback beside `addDiffSurface` (`:3185-3197`); a `case "plan":` in the content switch (`:5899-5969`) rendering `planPanel`. Deliberately generic, so weekly upstream merges stay cheap and `ChatView` learns no Mercurian types.

**Content (Mercurian, new):** `apps/web/src/components/mercurian/SessionPlanPanel.{tsx,logic.ts}`, composed by the session route as `planPanel={planId ? <SessionPlanPanel planId={planId} sessionLeafCommitId={record.commitId} /> : undefined}` — the route's tree scan (`:89-93`) already yields the record; extend its lookup to carry `commitId`. The panel:

- subscribes `usePlanDetail(planId)` (`state/mercurian.ts:110-127`), builds the graph (`buildPlanGraph`), finds the leaf node, and reads `planRevisionCommitId` from the leaf's timeline item (`contracts/mercurian.ts:322-328`) with `parents[0]` as the base;
- fetches text via `useGetPlanTextAt` (the `PlanningSpace.tsx:408-431` fetch-into-state pattern) and renders it read-only with `PlanArtifactBody`, headed by the plan title — "Plan for <repo>" when the implemented revision carries a split stamp (the `planCommitSummary` wording, `PlanGraph.logic.ts:316-320`);
- shows the **moved-past notice** when the pure predicate in `SessionPlanPanel.logic.ts` says so (Section 5);
- handles the quiet states: plan pending → skeleton; empty plan text → "No plan revision preceded this session."; no leaf found (reverted/foreign thread) → the panel's empty state.

No new store, no new RPC, no parallel data path: one existing subscription plus one existing unary call, exactly the issue's adaptation boundary.

### 5. "The plan has moved past this session" is a pure derivation

`sessionPlanReading(graph, leafCommitId)` in `SessionPlanPanel.logic.ts` returns `{ planRevisionCommitId, baseCommitId, movedPast, movedPastRepositoryName }`:

- **Base movement:** the base commit (`parents[0]`) has a child, other than this leaf, that is neither a coding-session leaf (a sibling implementation is not the line moving on) nor a split-stamped plan revision (a projection landing beside you is not the line moving on — the exclusion `planMovedPastSplit` already encodes, `PlanNodePopover.logic.ts:83-87`). Any other child — message, ordinary plan revision, spec revision — means planning continued past the session's start.
- **Split staleness:** when the implemented revision carries a split stamp, additionally consult the existing `planMovedPastSplit(graph, planRevisionCommitId)` — the parent plan line moving past the split is exactly the vault's "position is the stamp" fact, and it must surface here even when the split branch itself never moved.

Either condition sets `movedPast`; the notice reuses the M-133 copy family — "Planning has moved past this plan" (+ " for <repo>" in the split case, `PlanNodePopover.tsx:338-342`) — worded for a user, never saying "split". Nothing auto-reconciles and nothing navigates on its own: the notice is information, with the header's plan crumb (M-117) as the way back to planning.

### 6. The preview offer returns, on the session header

`apps/web/src/components/mercurian/SessionPreviewOffer.{tsx,logic.ts}` **(new)**, rendered by `CodingSessionHeader` after the title: on desktop (`isPreviewSupportedInRuntime()`), when `useThreadDiscoveredPorts` reports thread-attributed listening ports, a chip per port (label from the logic file — `localhost:5173`-style host:port) that calls the existing `openDiscoveredPort({ threadRef, port, openPreview })` (`preview/openDiscoveredPort.ts:13-28`) — which opens the preview session and activates the browser surface — with the `LegacySidebar` toast on failure (`:418-440` precedent). On the web client the chip renders nothing: the disabled Browser tab with its reason (already built, Section "Discovery") is the designed message there. The in-panel offers (`PreviewEmptyState` merging discovered ports and configured script URLs) continue untouched. Port discovery attribution requires the port's process to have been spawned from a session terminal — true for dev servers started in the terminal tab; script-declared preview addresses arrive with M-119.

### 7. Documentation and surface accounting

- `docs/architecture/fork-baseline.md` §2: amend the disposition table — t3code's plan-mode proposals surface (already removed upstream at right-panel storage v9; mode stripped at M-114) is **replaced on the session screen by the session's standing Plan tab** at M-118: "the difference between a plan as a turn's output and a plan as the reason the session exists."
- `docs/user/projects-and-plans.md`: the session screen's right panel — the five tabs, diff scopes and toggles, commenting on diff lines and how chips travel with the next message, the plan tab and its moved-past notice, the preview offer and the web client's disabled tab.
- `docs/internals/glossary.md`: review comment, whole-session diff, session plan tab.

## Decision Log

- **D1 (architectural) — The Plan tab is a new surface kind in the upstream panel store, not a Mercurian side panel.** The issue's boundary is explicit ("add no parallel panel state or data path"), and the store's own design comment says surfaces are thin descriptors over feature-owned state. Alternatives rejected: a Mercurian panel mounted beside `ChatView` (parallel state, double tab strips), and reusing upstream's removed v9 `plan` kind semantics (nothing to reuse — the kind, triggers, and renderer are gone).
- **D2 (architectural) — Content crosses `ChatView` as `planPanel?: ReactNode`,** M-117's `headerContent` precedent: one generic prop, availability derived from its presence, zero Mercurian types upstream. A typed `sessionContext` prop was rejected for merge cost.
- **D3 (design-conformant) — "Whole session" is the checkpoint diff `0 → latest`, not "Branch changes" with the session base.** Checkpoints capture the session's whole working-tree arc regardless of commits (the agent doesn't commit; M-119's git actions will), and the endpoint plus client routing already exist. Branch changes stays as the fourth scope — reuse, not redesign; the AC enumerates, it doesn't exclude.
- **D4 (design-conformant) — Replacement is exact-anchor replacement in the draft store.** The vault says "replaced if you comment on the same lines again"; equal `(sectionId, filePath, startIndex, endIndex)` is that sentence in the store's own anchor vocabulary, implemented where every add already flows, preserving the file-viewer's same-id remap. Fuzzy overlap-merging was rejected as an unrequested semantic.
- **D5 (architectural) — `DiffPanel` gets its thread by prop; route resolution stays as fallback.** Making `resolveThreadRouteRef` primary-environment-aware would give a parked route family new semantics to fix one mounted consumer; the prop is smaller and matches how every other panel child already receives its thread.
- **D6 (design-conformant) — The preview offer is a header chip on the Mercurian-owned session header.** "Offers itself" needs unprompted visibility; the built referent (the sidebar port chip) lost its mount with the app-shell reshaping. The header is the session's one always-visible Mercurian surface, and the chip reuses `openDiscoveredPort` whole. Auto-opening the panel was rejected — t3code never opens surfaces uninvited.
- **D7 (local) — The agents tab and the bottom terminal drawer stay.** Vault omission is not removal (M-117's rule); both are working-tree machinery a session legitimately has, and stripping them is a vault-citable act this issue doesn't carry.
- **D8 (local) — Moved-past excludes sibling implementations and landed projections.** A sibling session or a split landing beside you is the plan's designed branching, not the line leaving you behind; the exclusion mirrors `planMovedPastSplit`'s own child filter, and the split-stamp case additionally surfaces the existing parent-line check so "position is the stamp" reads on the session screen too.
