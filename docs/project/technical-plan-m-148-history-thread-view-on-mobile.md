# Technical Plan — M-148: History Thread view on mobile

_Generated from the Goal/AC of Linear issue M-148 (see the issue for the full AC). Branch `venk/m-148-history-thread-view-on-mobile`, stacked on `venk/m-147-mobile-planning-space` (itself on `venk/m-146-mobile-plan-list`); this plan lands in the repo as `docs/project/technical-plan-m-148-history-thread-view-on-mobile.md`. Design sources are the almagest vault notes **Checkpoint Graph** (the Thread view: "exactly the path through where you stand, root to tip, read as a thread. Divergence never hides"; picking navigates, per the resolved selection semantics; published vs. private in every view) and **Commit Tree** (invariant 1: "forks and merges are human-driven only" — continuing from an earlier checkpoint is a fork, and the composer is where you act from it). The phone shows **Thread only**: Columns is deliberately excluded at phone width, and the spatial Graph map is M-149._

_Stack caveat, stated up front: at planning time `venk/m-146` and `venk/m-147` still point at `main` (`d1731ae88`) — their plans are being authored in parallel. This plan treats their deliverables as present (a mobile plan-detail bridge over `createMercurianPlanningAtoms`, and a planning-space screen with conversation, composer, and artifact toggle) and names the seams it needs from them. Where M-147's plan makes an overlapping choice — most plausibly around plan position, which its "the path I'm standing on" AC also needs — reconcile at rebase: the shared modules below are the superset either issue needs, so the overlap collapses into consuming them._

**Goal, in one sentence:** the phone gets the Checkpoint Graph's Thread reading — the checked-out path as one checkpoint-per-row list with always-visible divergence badges — and picking a checkpoint moves the mobile planning surface to its terminal state so the composer forks from there; the checkpoint/position model that powers it moves to a shared package where web keeps using it and M-149's Graph map can import it next.

## What discovery found

- **The whole feature is a client-side rendering; the wire already carries everything.** `subscribePlan` streams every commit of the plan's DAG — all branches, not just the current path — folded by the pure reducer [planReducer.ts](../../packages/client-runtime/src/state/planReducer.ts), whose own doc-comment says why it lives where it does: "Pure, so web and mobile share it." `MercurianAppendPlanMessageInput.parentCommitId` ([mercurian.ts:636](../../packages/contracts/src/mercurian.ts)) is the fork mechanism, server-enforced: "Naming a commit that already has a child is how a fork is made, and the only way one can be." Nothing in `packages/contracts` or `apps/server` changes.
- **The desktop Thread is already split into framework-free logic the phone can run unchanged.** `threadLayout`/`mostRecentTip`/`branchOption` in [PlanThread.logic.ts](../../apps/web/src/components/mercurian/PlanThread.logic.ts), the continuable-checkpoint condensation in [PlanCheckpoints.logic.ts](../../apps/web/src/components/mercurian/PlanCheckpoints.logic.ts) (M-132), the graph build and traversals in [PlanGraph.logic.ts](../../apps/web/src/components/mercurian/PlanGraph.logic.ts), and the position model in [PlanPosition.logic.ts](../../apps/web/src/components/mercurian/PlanPosition.logic.ts) import only `@t3tools/contracts` and each other — with one exception: `PlanGraph.logic.ts` also exports the spatial `dagLayout` and imports `d3-dag` at module top, so hoisting that file wholesale would drag d3-dag into every consumer's bundle.
- **How the desktop view consumes them** ([DagExplorer.tsx](../../apps/web/src/components/mercurian/DagExplorer.tsx)): condense with `useMemo`; `currentCommitId = planNodeIdForCommit(anchoredCommitId ?? graph.latest, nodeIdByCommit)`; `isUnansweredCheckpointInFlight` suppresses the Unanswered chip for the streaming turn (fed by `detail.inFlightTurn?.parentCommitId`); rows are `CheckpointRow` (query line right-aligned with the mirrored You bubble, effect chips, response line with the Assistant bubble, relative time) or `CommitRow` (kind glyph + summary + time), published reading solid and private muted; the trailing `DivergenceBadge` is an always-visible `⑂ n/N` button whose flyout lists `branchOption`s (summary, last-active time, published treatment, current marked inert); choosing a sibling calls `onSelect(option.tipId)`, a merge's parent-line choice writes per-window `parentChoices`. [PlanningSpace.tsx](../../apps/web/src/components/mercurian/PlanningSpace.tsx) holds `useState<PlanPosition>`, runs `advance` on every graph change, resolves `head`, sets position live at `sent.commitId` after a send, and shows `ViewingEarlierBanner` ("Viewing an earlier point — sending starts a new branch from here") with **Back to now**.
- **Mobile already speaks the protocol and has the runtime.** `apps/mobile` depends on `@t3tools/client-runtime` and `@t3tools/contracts`; [connection/runtime.ts](../../apps/mobile/src/connection/runtime.ts) builds the same `connectionAtomRuntime` the web's state layer feeds to `createMercurianPlanningAtoms` ([mercurianPlanning.ts](../../packages/client-runtime/src/state/mercurianPlanning.ts), the factory [apps/web/src/state/mercurian.ts](../../apps/web/src/state/mercurian.ts) already instantiates). M-146's bridge is the mobile twin of that web state file; both history screens below read the _same_ plan atom family, so the history view costs no second subscription.
- **The shared-versus-copy question has a settled precedent.** `packages/client-runtime/src/state/projectGrouping.ts` is shared derivation logic consumed by web and adapted by `apps/mobile/src/state/project-grouping.logic.ts` — shared core in `client-runtime/state` with colocated tests, thin per-client adapters. Both sides' tests use `vite-plus/test` and run via `vp test run`, so moving a suite is a file move. No web file outside `apps/web/src/components/mercurian/` imports the four logic modules, and this stack does not contain M-141's fixture builders (the logic tests still hand-build commits locally), so the moves carry no fixture dependency.
- **Mobile surface conventions.** Screens are `features/<area>/FooRouteScreen.tsx` (wiring) + `FooScreen.tsx` (view), registered in [Stack.tsx](../../apps/mobile/src/Stack.tsx) via `createNativeStackScreen`; sheets are formSheet-presented screens (the `features/threads/git/*Sheet.tsx` family); styling is uniwind `cn()` over t3 tokens (`text-foreground-muted`, `font-t3-*`) with `AppText`; icons go through [AppSymbol.tsx](../../apps/mobile/src/components/AppSymbol.tsx) (SF Symbol names on iOS, a tabler map for Android — new symbols extend `ANDROID_ICON_BY_SF_SYMBOL`); long lists use `@legendapp/list`; relative time from `lib/time.ts`; transient client state is effect Atoms on `appAtomRegistry` ([atom-registry.ts](../../apps/mobile/src/state/atom-registry.ts)) read through `@effect/atom-react`.
- **ADR 004** ([fork-baseline.md](../architecture/fork-baseline.md)): Mercurian code stays additive beside upstream's, minimal edits inside upstream-owned files. Mobile's _parked_ disposition is being revived by this stack; recording that revival belongs to the stack's first issue (M-146), not here.
- **Vault specifics the AC leaves implicit:** where lines merge, the badge shows the other incoming lines and choosing one "re-roots what you're reading without moving you" (a reading, not a navigation); a merge is drawn once; the node popover is a desktop idiom whose touch translation (a detail sheet) is designed under M-149, so Thread rows on the phone pick on tap and defer per-checkpoint disclosure.

## Design

### The history model hoists into client-runtime — moved, not copied

Copying the logic into `apps/mobile` would fork "the same history draws the same picture in every window" the day either copy drifts, and M-149's map needs the same modules again (plus `dagLayout`). The shared package is where this code was already headed — the reducer beside it says so — and mobile imports it today. So the four modules **move** (files relocated, web imports updated; no re-export shims, matching how `apps/web/src/state/mercurian.ts` imports the package directly):

- **`packages/client-runtime/src/state/planGraph.ts` (new, moved)** — `PlanGraph`/`PlanGraphNode`/`PlanCheckpoint`/`PlanCheckpointEffect`, `buildPlanGraph`, `ancestorClosure`, `descendantClosure`, `hasFork`, `planCommitSummary`, `planCommitDetail`. Export `./state/plan-graph`. **What stays web-side in the residual `PlanGraph.logic.ts`:** `dagLayout` + the spatial types (its `d3-dag` import must not enter the shared package — or the mobile bundle — until M-149 chooses where the map layout lives; give it its own subpath then so Thread-only consumers never load it), and `PlanExplorerView`/`effectivePlanExplorerView` (the three-view vocabulary is a per-client fact: the phone has one view now and gains Graph, never Columns).
- **`packages/client-runtime/src/state/planCheckpoints.ts` (new, moved)** — `condensePlanGraph`, `CondensedPlanGraph`, `mapMarksToNodes`, `planNodeIdForCommit`, `isUnansweredCheckpointInFlight`, `planCheckpointEffectLabel`, `planNodeSummary`, `planNodeDetail`. Export `./state/plan-checkpoints`. **Exception:** `planNodeStatusDots` returns Tailwind `fill-*` classes — web presentation, one consumer — so it moves into [DagExplorer.logic.ts](../../apps/web/src/components/mercurian/DagExplorer.logic.ts) (the web explorer's presentation-logic module), its cases into that module's test.
- **`packages/client-runtime/src/state/planThread.ts` (new, moved)** — `threadLayout`, `mostRecentTip`, `branchOption`, the `ThreadRow`/`ThreadSwitch`/`BranchOption` types. Export `./state/plan-thread`.
- **`packages/client-runtime/src/state/planPosition.ts` (new, moved)** — `PlanPosition`, `LATEST`, `resolveHead`, `resolveActingHead`, `positionAfterPick`, `advance`, `isViewingPast`. Export `./state/plan-position`.

Tests move with their modules (`planThread.test.ts`, `planCheckpoints.test.ts`, `planPosition.test.ts` colocated in `client-runtime/src/state/`); `PlanGraph.logic.test.ts` splits — graph-model cases move to `planGraph.test.ts`, `dagLayout` cases stay web. Web consumers updated in place: `PlanningSpace.tsx`, `DagExplorer.tsx`, `DagExplorer.logic.ts`, `PlanColumns.logic.ts` (+ its test), `PlanNodePopover.logic.ts`/`.tsx` (+ tests), `PlanTimeline.tsx` if it reads summaries. No behavior change on web is intended or accepted; the moved suites and the untouched web component tests are the proof.

### Position becomes a per-plan atom, because two screens now stand in one place

On desktop, position is `useState` inside `PlanningSpace` — one window, one component. On the phone the planning space and the history are two routes over one standing place, so the same ADR 002 scroll-state-shaped fact lifts one level, no further: **`apps/mobile/src/state/plan-position.ts` (new)** holds a per-plan `Atom.family` of `{ position: PlanPosition, parentChoices: ReadonlyMap<string, MercurianCommitId> }` on `appAtomRegistry` — in-memory only, never persisted, reset when the plan's planning space unmounts (leaving the plan is closing the window). A `usePlanPosition(planRef, graph)` hook wraps it: reads position, applies `advance(graph, position)` as commits land (the desktop's `useEffect` on graph change), and exposes `pick` (`positionAfterPick`), `standAt` (post-send live placement), and `backToNow` (`LATEST`). `parentChoices` rides in the same family because the branches sheet (a separate route, below) must write the choice the history screen reads — react-navigation params can't carry callbacks — and a merge's re-rooting is exactly as transient as position itself.

The M-147 seam, stated as a contract: the planning-space screen resolves `head = resolveHead(graph, position)`, filters its conversation by `ancestorClosure(graph, head)`, and the composer sends `appendPlanMessage` with `parentCommitId = resolveActingHead(graph, head)`, then `standAt(sent.commitId)`. If M-147 built a local equivalent, this issue replaces it with the shared hook; if it pinned to `latest`, this issue threads position through. Either way M-148 adds the planning-space affordance that keeps a picked past honest: the mobile `ViewingEarlierBanner` twin — shown when `isViewingPast`, "sending starts a new branch from here", with **Back to now** — since without it, picking an earlier checkpoint strands the user in the past with no visible way home.

### The screen: a pushed full-screen route, rows the shared layout already computes

**`apps/mobile/src/features/plans/PlanHistoryRouteScreen.tsx` + `PlanHistoryScreen.tsx` (new)** — registered in `Stack.tsx` as `PlanHistory` (plain push, params `{ environmentId, planId }` following the thread-routing param shape), entered from a **History** button this issue adds to the planning-space header (`AppSymbol`; extend the Android map as needed). A pushed route rather than a pane or sheet because the list wants the whole phone height, and M-149's map "opens full-screen from the plan's history" — this screen is the place it will open from. The screen reads the _same_ plan atom the planning space holds (M-146 bridge; the family memoizes per environment+plan, so no second `subscribePlan`), then derives exactly as desktop does, through:

**`apps/mobile/src/features/plans/plan-history-model.ts` (new, + colocated test)** — the mobile adapter in the `project-grouping.logic.ts` mold, pure over `(PlanSubscriptionState, position, parentChoices)`: build the commit graph, condense, `threadLayout(condensed, currentNodeId, parentChoices)` where `currentNodeId = planNodeIdForCommit(resolveHead(commitGraph, position) ?? latest, nodeIdByCommit)`, the in-flight-unanswered suppression set from `detail.inFlightTurn?.parentCommitId`, and per-badge `branchOption` lists. Everything view-shaped and testable without React.

**Rows** (**`plan-history-items.tsx` (new)**, in the `thread-list-items.tsx` mold, rendered in a `@legendapp/list` with variable row heights, initially scrolled to the current row): the phone re-renders the desktop grammar natively —

- A checkpoint row: query line right-aligned with the You bubble glyph, effect chips (`planCheckpointEffectLabel`: Plan updated / Spec updated / Interrupted / Unanswered, the last suppressed while that turn streams), response line left-aligned with the Assistant bubble glyph and relative time (`lib/time.ts`). Glyphs via `AppSymbol` — `bubble.right` for You, `bubble.left` for Assistant (SF has both orientations natively; Android maps tabler `IconMessage`, mirrored for You), labels kept where room allows, `accessibilityLabel` always naming the author so identity never rides the mirror alone.
- A standalone-act row: kind glyph + `planCommitSummary` + relative time — direct plan/spec edits, refreshes, splits, coding-session leaves, merges.
- **Published vs. private:** published text on `text-foreground`, private muted (`text-foreground-muted`/`-tertiary`) — the token-for-token mobile reading of the desktop treatment. (Publishing is still unbuilt server-side; `published` is uniformly `false` on the wire, so this ships dark and is pinned by fixtures, exactly as it did on desktop since M-125.)
- **Where I stand:** the `currentNodeId` row gets the accent background and `accessibilityState: { selected: true }`, the RN reading of `aria-current`.
- **Tapping a row picks it** — `pick(commitId)` then `navigation.goBack()`: the planning surface behind is already standing at the checkpoint's terminal state when it fronts, and the composer continues from there. Navigate-on-pick is the vault's resolved selection semantics; popping is what "moves the planning surface" honestly means when the surface is another screen. No linger-popover on rows: per-checkpoint disclosure on touch is the detail sheet M-149 designs.

**Divergence badges → a branches sheet.** Rows with `siblings`/`parentLines` carry the always-visible badge (fork or merge glyph + `n/N`, its own tap target with generous `hitSlop`, never triggering row-pick). Tapping opens **`PlanBranchesSheet.tsx` (new)** — a formSheet route (`PlanBranches`, params `{ environmentId, planId, commitId, kind }`) in the git-sheet mold, deriving its options live from the same subscription: one row per `branchOption` (summary, last-active relative time, published treatment, current option checked and inert). Choosing a sibling sets position to `positionAfterPick(commitGraph, option.tipId)` — the branch's most recently active tip, standing live — and dismisses; the history list beneath re-renders onto the new path with the marker moved, which keeps branch-hopping fluid without bouncing through the planning space. Choosing a parent line writes `parentChoices` and dismisses — re-rooting the reading above the merge, moving nothing, per the vault. Opening the sheet never navigates; only choosing does.

### What deliberately does not change, and what is out of scope

The wire, the server, the reducer, and every desktop behavior (the moved modules must leave web pixel-identical). Out of scope, each deliberate: **Columns** on phone (excluded by the issue; the vault's fallback grammar covers a future tablet width); the **Graph map**, the **node popover/detail sheet**, and any per-checkpoint disclosure surface (M-149); **implement-from-here, ready/stale marks** on rows (M-150 brings the implement moment; the marks arrive with their acts rather than as inert chips); **edit-and-branch** (M-134, unbuilt on desktop); view persistence (one view, nothing to persist — desktop's `mercurian:dag-explorer-view:v1` key is web's own). Merges remain representable-but-not-creatable, so parent-line switching ships against fixtures, like every prior history issue.
