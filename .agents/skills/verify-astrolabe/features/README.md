# Astrolabe feature map

Astrolabe's own user-facing features, the parts upstream T3 Code does not have.
Everything else verifies through [test-t3-app](../../test-t3-app/SKILL.md).
Each file covers what the feature is, how a user reaches it, how to drive it in
the Browser panel (its **Mobile** entries through
[test-t3-mobile](../../test-t3-mobile/SKILL.md)), the end state that proves it, and
the source files it owns.

The file names are older than the feature names: repositories.md is Projects and
pull-requests.md is Changes.

The panes engine is shared: a change in `panes/` walks panes.md, code-graph.md, project-docs.md,
repositories.md and pull-requests.md. A change to row clicks or tab history
(`tabNavigation.logic.ts`, `panes/TabHeader.tsx`'s Back/Forward) walks panes.md, project-docs.md,
repositories.md and pull-requests.md, and one to the project filter
(`components/projects/`) walks sidebar-header.md, repositories.md and
pull-requests.md. The keyboard menu calls into the panes, the sidebar,
Projects and Changes, so after any of those changes walk which-key.md's
flows too; vim-mode.md's flows cross the composer, notes, Projects files and the
palette. A change to `components/repositories/` or the Docs filter walks project-docs.md
too, and `packages/wiki-editor/` holds `CanvasBoard.tsx`, so a change there walks canvas.md
too. keyboard-nav.md reads the sidebars' rows, the chat column and the panes by
their data attributes, so a change to any of them walks it too.

When a sync conflicts in one of the owned files, or when upstream rewrote what
an owned file wraps (ChatView's header and right panel, the sidebar), walk that feature
before the others.
