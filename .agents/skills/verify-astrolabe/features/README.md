# Astrolabe feature map

Astrolabe's own user-facing features, the parts upstream T3 Code does not have.
Everything else verifies through [test-t3-app](../../test-t3-app/SKILL.md).
Each file covers what the feature is, how a user reaches it, how to drive it in
the Browser panel (its **Mobile** entries through
[test-t3-mobile](../../test-t3-mobile/SKILL.md)), the end state that proves it, and
the source files it owns.

The panes engine is shared: a change in `panes/` walks panes.md, wikis.md,
repositories.md and pull-requests.md. A change to row clicks or tab history
(`tabNavigation.logic.ts`, `SidebarTabHistory.tsx`) walks chat-tabs.md, wikis.md,
repositories.md and pull-requests.md, and one to the project filter
(`components/projects/`) walks sidebar-header.md, wikis.md, repositories.md and
pull-requests.md. The keyboard menu calls into chat tabs, panes, the sidebar, Wikis,
Repositories and Changes, so after any of those changes walk which-key.md's
flows too; vim-mode.md's flows cross the composer, notes, Repositories files and the
palette. keyboard-nav.md reads the sidebars' rows, the chat column and the panes by
their data attributes, so a change to any of them walks it too.

When a sync conflicts in one of the owned files, or when upstream rewrote what
an owned file wraps (ChatView's header and right panel, the sidebar), walk that feature
before the others.
