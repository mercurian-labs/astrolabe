# Atlas editor: collaboration specification

Status: draft 6, 2026-09-30. Draft 6 adds the arrival rule: a write lands at once in the document and is revealed gracefully by presentation alone, never by streaming operations (B21, B22). Draft 5 added the agent's cursor moving ahead of its write and the follow option that keeps that cursor in view, so a person can watch a change land (B20). Draft 4 ruled that Dismiss hides a ghost but keeps the deletion, so a later revert of the entry or the turn still restores it (found by the first walk: dismissing a ghost, then Revert all, left a lone period where three bullets had been). Draft 3 recorded the origin of every deleted character (not only the agent's own) so a turn revert re-anchors earlier ops inside restored text, keeps op indexes stable, and ignores malformed remote entries (B18, B19; B12 extended), after the second review. Draft 2 amended the bridge diff (semantic cleanup, no widening), gives entries a clock range and ops an ownership record so accept and revert are exact, rules on ghosts inside replaced ranges and on the end-of-text anchor, and adds B16 and B17 after the first review of the proof of concept. Draft 1 was the first contract. This document is the contract for `@mercurian/editor`'s collaboration layer: the agent peer, the file bridge, attribution, and the agent change log with its ghosts and review lifecycle. The live-preview specification (`live-preview-spec.md`) owns everything about rendering Markdown and refers here for what it calls "the agent highlights". Tags are as there: **DECIDED** is our ruling; **BUILT** marks what the branch already does; **LATER** marks a decision recorded now and built in a later slice.

Sources: the Atlas Editor note in the product vault (two peers on one document, the file is the source of truth, the buffer is working state), the product owner's rulings of 2026-09-28 through 2026-09-30 (agent to user is live; user to agent waits for the end of the turn; steering is shelved; a deletion is carried out and shown as a ghost the user can restore), and the existing bridge and attribution code.

## 1. Model

1. **The file is the source of truth; the buffer is working state.** Each open note is one Yjs document holding one `Y.Text`. The user's editor is a view over it through `y-codemirror.next`. The agent never holds an editor: it writes the file in the thread's working state, and an **agent peer** (its own `Y.Doc` and `Awareness`, its own client id) turns each file write into Yjs operations through the bridge. DECIDED, BUILT (the playground's fake agent is this peer).
2. **Agent to user is live.** Every file write the agent makes reaches the user's editor as soon as the watcher sees it, one Yjs transaction per write. There is no staging, proposal, or suggestion mode: the text lands, attributed and reviewable after the fact. DECIDED.
3. **User to agent waits for the end of the turn.** While a turn runs, the user's edits live only in the buffer; the file on disk stays what the agent last wrote. When the turn ends, the buffer is written to the file and becomes the bridge's new base. No merge step is needed: the buffer already is the merge. Steering the running turn with the user's edits is recorded as an idea and not built (noise, agent re-reads). DECIDED, LATER for the flush itself (the playground simulates it).
4. **The diff base is what the agent wrote.** The bridge diffs each new file text against the file text after the previous write (or after the last flush), never against the buffer. Because the user never flushes mid-turn, that base is exactly what the agent read. DECIDED, BUILT.
5. **Deletions are carried out.** When an agent write replaces or deletes a region, the bridge deletes that region of the buffer as it stands, including characters the user typed there since the last flush. The buffer stays a faithful merge of the file and the user's edits; the CRDT is not second-guessed. What left the buffer is shown as a ghost (section 4) and can be restored by the user. DECIDED (overrides the earlier idea of stepping over the user's items).
6. **Nothing in this layer reaches the file except text.** Attribution, the change log, and ghosts live in the Yjs document, never in the Markdown. `text.toString()` is always the file's next content. DECIDED.
7. **Presentation never moves the caret or the scroll position** on a remote change (live-preview spec, principle 5). Navigation between changes is an explicit user action and does move the caret. DECIDED.

## 2. The agent peer and the bridge

- **Presence.** The agent declares itself in awareness with a name, a colour, and the turn id it is working in (`declareAgent`). Its cursor moves to where it is about to write **before** the write lands, and parks at the end of the edit afterwards (`parkAgentCursor`); it renders through `yCollab`'s remote selections with the name always visible. The gap between the cursor move and the write is what lets a following editor scroll first (section 4, following); the playground uses a fixed beat, and the env-plane peer does the same once it knows the write's first edit. When the turn ends, the presence drops its turn id (or the peer leaves). BUILT.
- **The bridge.** `applyFileText(text, previous, next)` applies the character diff from `previous` to `next` onto `text` in one transaction (the diff gets fast-diff's semantic cleanup, so a rewritten phrase is one edit rather than a scatter of shared letters, and no widening beyond that: an edit that only inserts or only deletes stays exactly that, so untouched characters keep their Yjs identity and a user's characters inside an untouched word survive), mapping the edits onto the current buffer when it has moved on (user edits outside the replaced regions survive; inside them they are deleted, per 1.5). BUILT. The bridge additionally **records** each write in the change log (section 3): one entry per write, with the text each deletion removed from the buffer, read from the buffer before the delete so a user's unsent words inside the region are in the ghost. DECIDED.
- **The env-plane peer** (the watcher on the working-state file, the sync provider over the T3 socket, persistence of the document under T3 home, the flush at turn end, attribution of writes outside any turn as external and uncoloured) is specified here in outline and built in a later slice. LATER.

## 3. The change log

- **Shape.** A `Y.Array` named `agentChanges` in the same `Y.Doc` as the text. Each element is a plain object: `{ id, turnId, client, name, color, at, ops }` where `ops` is a list of `{ from, to, deleted }`: `from` and `to` are encoded Yjs relative positions bounding what the write inserted (equal when it inserted nothing; `to` associates left so typing at the end of the insertion does not grow it), and `deleted` is the buffer text the write removed at `from` (empty when it removed nothing). Positions are relative so the entry stays anchored under concurrent typing. Each entry also carries `clock`, the half-open range of the writer's Yjs clock spanned by the characters the write inserted: every inserted character carries its client's clock, so which write owns a character is decidable without positions. Each op records `items`, the origin of every character of `deleted` as runs of (offset, length, client, clock), so a turn can be reverted exactly: the agent's own characters are the runs with the entry's client and a clock in its range, and an earlier op whose anchor item was deleted by a later write is re-anchored inside the text that write's revert restores. An op whose anchor is at the very end of the text sticks to the character before it (a right-associated end position would follow everything appended later), and the op records that association so the editor maps it the same way locally. DECIDED.
- **Who writes it.** Only the agent peer, from the bridge, inside the same transaction as the text change. The editor never infers a deletion from the CRDT (a deleted item carries its author's id, not its deleter's, so inference fails with a second agent or an external editor). DECIDED.
- **Who removes entries.** The user, through accept, revert, and dismiss (section 5), and the host through `clearAgentChanges(doc, turnId?)` when the thread commits, since the commit is the durable record. The undo manager is scoped to the text and never touches the log. DECIDED.
- **Ephemeral.** The log is document state, not file state. It survives a reload only once the document is persisted (LATER). DECIDED.

## 4. What the user sees

- **Insertions** are marked in the agent's colour (`atlas-agent-change`), attributed by the Yjs client id of each inserted item. Characters the user types inside an agent's insertion are carved out and stay plain. BUILT.
- **Deletions** show a **ghost**: an inline widget at the deletion's anchor holding the deleted text, struck through, tinted in the agent's colour, inert to editing keys (the caret steps over it; Backspace and Delete never touch it). A deletion longer than one line, or longer than roughly eighty characters, renders collapsed: its first line trimmed, then a count of the remaining lines; clicking the collapsed ghost expands it in place. DECIDED.
- **A click on a ghost** opens a small popover next to it with **Restore** and **Dismiss**; Escape or a click elsewhere closes it. Restore inserts the deleted text at the anchor as a user edit (attributed to the user, its own undo step) and removes the ghost. Dismiss hides the ghost and changes nothing in the text; the deletion stays in the log, so reverting the entry or the turn later still restores it, and only accepting the entry (or clearing the log) forgets it. On an op that also inserted text they clear only its deletion, so the insertion stays reviewable; the op stays in place with its deletion cleared (op indexes never shift, so an open popover can never retarget another ghost), and an entry whose ops have neither an insertion nor a deletion left is removed. DECIDED.
- **Following the agent.** An optional extension, off by default and switched on by the person, keeps the agent's cursor in view: when an agent presence's cursor moves to a position outside the visible part of the editor, the view scrolls to centre it; a cursor move within view scrolls nothing. Visible means inside the editor's on-screen area minus the insets the host declares for chrome that covers it (a sticky header), so a write never lands behind the chrome. The follower reacts only to agent cursors, starts from the cursors as they are when it mounts, and never dispatches inside an editor update. The scroll itself is smooth: the follower scrolls the scrolling container (the editor's scroller when it scrolls, else the window) by the distance that puts the cursor's line at the band's centre, using the browser's native smooth scrolling, so it eases over roughly a third of a second and a wheel movement from the person interrupts it; under reduced motion it jumps. Because unrendered lines have estimated heights, the follower re-checks once the scroll has settled and corrects with one more scroll if the cursor is still outside the band. The agent's write lands after the scroll settles (the playground's beat is longer than the smooth scroll). The user's caret, selection, and focus are never touched, and nothing scrolls on accept, revert, dismiss, or the user's own edits. Because the agent's cursor moves ahead of its write, the write lands where the person is already looking. This is the one user-enabled exception to principle 1.7. DECIDED.
- **Arrival.** A write is applied to the document at once, so the text is correct at every instant and the parser never sees a half-written construct; streaming the operations is ruled out because the file is already complete and the buffer would lie for the length of the animation. What is graceful is the presentation, through an optional extension the host installs: each inserted range of a new entry is revealed from its start, the not-yet-revealed tail hidden in place by a mark that keeps its layout (the text is invisible, not collapsed) and advances every animation frame, so the reveal never changes the document's height and the view never drifts while text flows in (the write itself is the only height change, at the moment it lands), and the boundary never rests inside an inline construct whose rendering pads it (inline code, tags, inline math), stepping over such a construct whole, since a split padded span would widen and could change a wrap mid-reveal, at a pace of roughly eight milliseconds per character clamped between 150 and 800 milliseconds per range, so a whole-paragraph rewrite never becomes a wait; ranges of one write reveal concurrently; a ghost that belongs to an entry younger than 300 milliseconds is drawn with an arriving class so it can fade in. The hidden tail only ever covers characters the write inserted: the moment the user's selection touches it, or a user edit lands inside it, the reveal finishes at once. A reveal inside a range the live preview replaces (a table, rendered math, frontmatter, a folded callout) has nothing to animate and finishes at once (fading the widget is LATER). Reduced motion (`prefers-reduced-motion: reduce`) disables the reveal and the fade. The reveal never dispatches a document change, never moves the caret or focus, and stops with the view. DECIDED.
- **Inside a replaced range.** A ghost whose anchor lies in a range the live preview replaces or hides (frontmatter, a folded callout, rendered math, a table, an image, hidden markers) is not drawn until the range reveals; Next and Previous land the caret on the anchor, which reveals it, and the change bar's count includes it. DECIDED for the proof of concept; a gutter marker for lines that carry hidden changes is LATER.
- **Turn grouping and settling.** Entries group by turn id. While an agent presence in awareness carries an entry's turn id, the entry's marks and ghosts are live; once no presence carries it, they get `atlas-agent-change-settled` and render dimmer. Settled entries stay until reviewed or cleared. DECIDED.
- **The change bar** (a CodeMirror panel, optional extension `agentChangeBar()`; a host may render its own chrome from the same commands instead): the count of entries, previous and next, and accept all and revert all. Hidden when the log is empty. DECIDED for the proof of concept; the product's chrome lives in the web package and reads the same state.
- **Whole rewrites.** A write whose ops cover more than a set share of the document is summarised by a banner instead of inline ghosts. LATER.
- **Inside an active table cell** the child editor shows neither marks nor ghosts. LATER (slice the outer decorations to the cell).

## 5. Commands

All exported from `./collab/agent-changes`, acting on the outer `EditorView`; each text change is one user undo step. DECIDED.

- `nextAgentChange`, `previousAgentChange`: move the caret to the start of the next or previous entry op in document order from the caret, wrapping, scrolled into view; false when the log is empty.
- `acceptAgentChange(view, id)`: removes the entry, the marks of exactly its characters (by clock range, so a later write nested inside keeps its marks), and its ghosts; the text is unchanged.
- `revertAgentChange(view, id)`: in one transaction, deletes the characters this write inserted (the items with the entry's client id and a clock in the entry's clock range, so characters the user typed inside stay, and so do a later write's characters nested inside) and inserts each op's deleted text at its anchor; then removes the entry. Deleted text is inserted as a user edit and is not re-marked.
- `restoreAgentDeletion(view, id, opIndex)`, `dismissAgentDeletion(view, id, opIndex)`: the ghost popover's actions.
- `acceptTurn(view, turnId)`, `revertTurn(view, turnId)`: over every entry of the turn. Revert goes newest first and carries ownership across its steps: text an earlier step restored keeps its characters' origins (per `items`), so the agent's own characters among them are removed when the write that inserted them is reverted, and an op whose anchor was deleted by a later write is placed by its anchor item's origin inside the restored text rather than at the collapsed point Yjs resolves; the turn's reversal is exact even when its writes overlap.
- `clearAgentChanges(doc, turnId?)`: the host's commit hook; removes entries without touching the text.
- `readAgentChanges(doc)` and `observeAgentChanges(doc, listener)`: what a host's chrome reads.

## 6. Acceptance catalogue

- B1. An agent write that inserts text shows the text marked in the agent's colour; the user's caret stays on the same character when the insertion lands before it. (Restates A60 and the existing attribution tests.)
- B2. An agent write that deletes `old words` shows a ghost holding `old words` at the deletion point, struck through, tinted; `text.toString()` does not contain `old words`.
- B3. Restore on that ghost inserts `old words` at the anchor with no agent mark, removes the ghost, and the user's undo removes `old words` again.
- B4. Dismiss removes the ghost and leaves the text unchanged; reverting the entry afterwards still restores the deleted text.
- B5. Typing ten characters before a ghost leaves the ghost anchored after the same character; typing at the exact anchor puts the typed characters before the ghost. At the very end of the text a ghost sticks to the character before it, so typing there lands after the ghost, and a remote refresh leaves it where local typing put it.
- B6. The user types `mine` inside a sentence; the agent's next write replaces that sentence; the ghost contains the sentence with `mine` in it, and the buffer holds the agent's replacement.
- B7. A deletion of three lines renders collapsed, showing the first line and a count; clicking it expands to the full text; a deletion of one short line renders expanded.
- B8. One entry per agent write; the change bar's count equals the number of entries; accept on an entry removes it and its marks and ghosts with the text unchanged; accepting a later write nested inside an earlier write's range removes only the later write's marks.
- B9. Revert on an entry that inserted `alpha beta`, into which the user typed `X` after `alpha`, leaves `X` and removes `alpha beta`'s characters; revert on an entry that deleted `gone` puts `gone` back at its anchor; both as one undo step.
- B10. Next moves the caret to the next entry op after the caret in document order and wraps; previous mirrors it; with an empty log both return false.
- B11. When the agent presence drops the turn id, the turn's marks and ghosts get the settled class; entries remain and still accept and revert.
- B12. Accept all removes every entry of the turn; revert all reverts them newest first and leaves the text as it was before the turn's writes, apart from the user's own edits, including when the writes overlap: a write that inserts `alpha` and a later one that replaces it with `beta`, with the user's `X` typed inside, revert to the pre-turn text plus `X`; and `a-----b` after a write that replaces `a` with `X` and `b` with `Y`, then a write that replaces `X-----Y` with `Z`, reverts to `a-----b`, with a variant where the user typed `u` in the separator between the two writes reverting to `a--u---b`.
- B13. `clearAgentChanges(doc)` empties the log and removes every decoration without changing the text.
- B14. In the playground, Run turn plays a scripted turn of several tool calls (an insertion, a sentence replaced, a paragraph rewritten, a list item deleted) while the user types; the marks and ghosts appear as each call lands, the user's caret stays put, and the File panel shows the file unchanged by the user's typing until the turn ends, when it equals the buffer.
- B15. The log is never in the text: after any sequence of the above, `text.toString()` contains no ghost text and no metadata.
- B16. With the live preview installed and the caret outside the frontmatter, an agent write that deletes inside the frontmatter draws no ghost; Next lands the caret in the frontmatter, and the ghost is drawn and opens its popover on click.
- B18. A log entry from a remote peer whose positions decode but do not resolve (or whose shape is wrong) is ignored without an exception, and later valid writes and commands still work.
- B19. With a ghost's popover open on the second of three deletions in one entry, another client dismisses the first; the popover still acts on the second deletion (or has closed), never on the third.
- B20. With following on and the agent's cursor out of view, the agent moves its cursor to its next write's position: the view scrolls to centre that position with the selection unchanged and focus not taken; the write then lands inside the visible range. A cursor move to a position already in view scrolls nothing; with following off nothing scrolls. In the playground the cursor moves a visible beat before each write lands.
- B21. With the reveal on, a logged write inserting 120 characters lands with the full text in the document and the selection unchanged, while a layout-keeping mark hides the insertion's tail (no replacing decoration is used, so the rendered line count and the content's height do not change as the reveal advances); as frames advance the hidden tail shrinks monotonically and is gone within 800 milliseconds; a user edit inside the range, or the selection moving into it, finishes the reveal at once; with the reveal off, or with reduced motion, no hiding decoration ever appears.
- B22. A ghost drawn for an entry younger than 300 milliseconds carries the arriving class; drawn later it does not.
- B23. With following on and the agent's cursor moving out of view, the follower asks the scrolling container for one smooth scroll by the distance that centres the cursor's line in the band; under reduced motion the same scroll is instant; after the scroll settles, a cursor still outside the band gets exactly one correcting scroll, and one inside gets none.
- B17. The bridge with `previous` `cat`, buffer `cXat`, and `next` `cats` yields `cXats` with `X` kept, with and without a log, and the untouched characters keep their items; a rewritten sentence yields a few ops, not one per shared letter.

## 7. Out of scope for this draft

Steering the running turn; the env-plane peer, watcher, persistence, and flush; the whole-rewrite banner; marks and ghosts inside active table cells; conflict presentation beyond the ghost; multi-agent turns (the model supports them; nothing here assumes one agent). Review by more than one client at once: entries are plain objects in the array and an op update replaces the element, so two clients reviewing the same entry concurrently would duplicate it; the product has one human per document (the vault's two-peer model), and per-op fields in a `Y.Map` are the change if that ever changes.
