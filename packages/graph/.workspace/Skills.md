# Skills

Skills are how a team teaches the [[Assistant|assistant]] its house style. The division of labor is deliberate: **Mercurian owns the substrate and its mechanics** — the [[Threads|thread]]'s line of checkpoints and the [[DAG]] between threads, the [[Memory|memory]]'s notes and links, the amendment commit — **and skills own how the work gets done inside it.** Productizing a substrate is not the same as productizing how it gets used: memory gives every team the same notes-and-links substrate, but "amend memory" alone cannot carry a team's house style — what a note is, how a decision is recorded, when research is done. Style is the team's, not the product's, and a team authors its own skills to customize it, per project. _(2026-09-16: this note once used the spec's two-field contract as its example; that document retired with the plan-first ruling on [[Mercurian]], and the division of labor survives unchanged.)_

Skills are a standing layer, not scaffolding: they remain the customization surface even once [[Memory]] is native. What dissolves into the product is memory's substrate — the research loop as grounding behavior, the amendment flow, the index; each genre's authoring conventions stay house style, carried in skills and in a skill map's body ([[Skill Maps]]).

## The skill map protocol

[[Skill Maps|Skill maps]] are the project-carried half of this layer, and beneath their variety sits a substrate the product owns — the protocol. It has two parts:

- **The base teaching.** The invariants every skill map inherits and none may override: notes hold truth, arrangement never mints an edge, red links are frontier, every product write is an amendment commit on the thread's branch — one amendment per commit and nothing else in it — curated at review and the merge home ([[Memory]]). The product states these once, to every agent, whenever a memory is designated; a skill map specializes them for its purpose and never contradicts them.
- **Deterministic utilities.** Mechanical transforms are computed, never free-handed. Renaming a note touches the file, every wikilink in every note, and every edge in every skill map — an agent hand-editing that many references will miss one, so it doesn't: the utility computes the complete transform. The write family covers adding an edge with its rationale and filling a red link; the read family covers the **orientation** — rendering a map's frontmatter into its derived walk and generated readings, since agents never meet frontmatter directly ([[Skill Maps]]) — and the **staleness forensics**, reconstructing which commit severed a link, which files moved, which maps' edges broke. The rule in one line: **the utility computes the diff, the commit carries it, your review curates it — the agent orchestrates but never free-hands a transform a utility could compute.** Utilities land ordinary amendment commits on the thread's own branch — one transform per commit, marked and revertible — so the agent's capability grows while everything it does stays curated at review and the merge home ([[Memory]], the 2026-08-31 write model). The family's boundary is [[Memory]]'s litmus: a utility moves notes, links, files, and diffs, and never interprets a note's meaning. _(2026-08-31: recording a resolution beneath its question left the family for exactly this — it reads a genre, so it belongs to a decisions map's teaching, with the review protecting what the guard once did.)_

The protocol's context law: **one document teaches which document to read or tool to invoke next.** Agents work best through multi-step discovery — memory is files an agent navigates and tools it calls, never a payload it receives whole. The base teaching orients toward the roster; a map's entry body orients toward its notes and its tools; depth is pulled when the work asks, never pushed. This law is why memory is files on disk, why frontmatter meets agents only through tools, and why every reading is generated fresh from authored atoms instead of stored.

## In the composer

The [[Composer]] carries the slash surface of the shell this design adapts: commands and skills supplied by the effective provider, invoked from the composer, the pattern documented as built in [[T3code Thread View]]. What a machine's installed agent doesn't offer is gated, not failed — the temperament of [[Providers]] — and an invocation is part of the message that carries it, recorded in the history like everything else a message stages.

## What exists today

**Codex workflow (2026-09-10).** The working memory now supplies project-carried product and decision teaching. A small standing instruction selects the task’s memory and loads its base rules and map roster; fuller teaching arrives when the agent consults a map. Navigation, renames, structural map edits, amendments, review, revert, and local promotion are available through the shared tools. The protocol is exercised here before further app integration. This does not make the app’s earlier injection and utility gaps disappear; the following records that earlier app delivery.

The composer's slash surface is built (2026-08): provider-supplied commands and skills, gated not failed, invocations recorded in the history. The skill-map file shape and its browse surface are built ([[Skill Maps]]); the protocol — the base teaching, the utilities, the orientation, the forensics — is not, and the memory's first implementation cut carries a hardcoded ancestor of the base teaching, one placement utility, and a genre parser the 2026-08-31 amendment retires.

## Open Decisions

### Are skills machine-local, or do they travel with the project?

Provider-supplied skills are machine-local: whatever the installed agent carries, which can differ per machine and per person. But a house style is team property — it wants to be versioned and shared, traveling with the project the way its [[Memory|memory]] does, rather than living on whichever machine happens to hold it. **Recommendation:** provider-supplied is the starting reality; project-carried skills — versioned beside the memory — are where this points, and the question should be settled in the same pass that designs memory designation.

**Resolved (2026-08-28): both, by kind — and the project-carried half arrived as [[Skill Maps|skill maps]].** House style that belongs to the project travels with it: a skill map is a skill versioned beside the memory it teaches, shared the way the notes are shared, reaching every machine the project reaches. Provider-supplied skills remain the machine-local reality for personal tooling and for style that hasn't moved into a memory. Given up: nothing the recommendation hadn't pointed at — the open half was where project-carried skills would live, and the memory answered it.
